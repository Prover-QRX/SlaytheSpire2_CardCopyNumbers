# 同名卡牌编号 / Card Copy Numbers

当前版本 **1.2.0**，作者 **祁若泫**。新版已编译到 `Workshop/content`，等待上传更新已有工坊条目。没有前置模组，不需要 BaseLib、RitsuLib、ModConfig 或 Godot 编辑器。

## 编号规则

- 显示示例：`打击 #1`、`打击+ #2`、`凋萎+2 #3`、`感染 #1`。
- 每个玩家、每场战斗各自编号；同名牌从 1 起分配，基础名称相同的牌归为一组，升级不会改变编号组。
- 开场卡牌按永久卡组中的顺序预分配，再映射到战斗卡牌，不按初始洗牌结果编号。即使从未打开牌堆，编号也已确定。
- 战斗中新加入的同名牌继续编号，包括状态牌和真实复制牌。仅用于预测或升级显示的副本继承原编号，不消耗新编号。
- 编号跟随卡牌跨手牌、抽牌堆、弃牌堆、消耗堆和出牌区移动，不会因为洗牌或查看牌堆而改变。
- 普通牌堆浏览中，同名牌的显示位置按数字递增整理。允许缺号，例如 #1 抽走后剩下 #2、#3；不会为了连续编号而重编号。
- 随机数预测的冻结之眼仍按真实/预测的抽牌顺序显示，数字用于辨认卡牌，不表示牌堆位置。
- 本场该名称只分配过 #1 时隐藏编号；一旦分配过 #2，该名称的编号持续显示，即使后来只剩一张。消耗、变化或移出战斗不会释放编号。预测副本不分配新编号。
- 卡牌被真正变化成另一种牌后，进入新名称的编号组。原编号不回收。

## SL 与兼容范围

针对本机游戏 **v0.111.0 / 41cef1ea** 构建；已参考本机 **RandomForeseer 0.13.14** 的冻结之眼和预览实现。

重开同一战斗，永久卡组顺序及实际生成牌的操作顺序相同，编号可复现。编号保存在内存中，不写入游戏存档；不承诺其他模组的“战斗中任意时刻快照恢复”会保留既有编号。改变操作顺序导致生成牌顺序改变时，后续编号也可能改变。

只修改显示名称和普通牌堆的显示副本，不修改实际牌堆、卡牌效果或随机数。采用 `affects_gameplay: false`。多人模式按各玩家独立编号，但尚未进行联网实机验证。

基础卡牌和凋萎的特殊名称均有补丁。第三方卡牌若完全重写 Title 且不调用基础实现，或其他模组完全替换牌堆 UI，可能需要单独适配。未来游戏/预测模组更新也需要重新检查接口。

## 上传创意工坊

官方上传器 v0.2.0 已下载到 `tools/ModUploader`。完整工坊工作区是本项目的 `Workshop` 文件夹，其中：

- `content/CardCopyNumbers.dll`、`content/CardCopyNumbers.json`：上传的模组文件。
- `workshop.json`：中英文介绍、标题和可见性。
- `image.png`：512×512 封面，约 12 KB。

1. 保持 Steam 已登录拥有本游戏的账号。
2. 如需修改署名，编辑 `Workshop/content/CardCopyNumbers.json` 的 `author`（当前为 `祁若泫`）。工坊发布者自动采用登录 Steam 的账号。
3. 打开本项目目录，在 PowerShell 运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Upload.ps1
   ```

   或双击 `上传到创意工坊.cmd`。这一步才会实际上传。
4. 当前工作区已关联条目 **3800734754**，运行脚本会更新此条目。`visibility` 设置为 `null`，保留工坊当前可见性，避免更新时将已公开条目改回私密。若 Steam 提示需要接受创意工坊协议，在网页完成接受。
5. **保留 `Workshop/mod_id.txt`**。上传器在成功创建条目后保存此文件，后续用相同脚本更新同一条目；删除它可能导致重复创建。
6. 更新时替换 `Workshop/content` 内的文件，修改版本号和 `changeNote` 后，再运行上传脚本。

不要把整个游戏目录、源码目录、反编译文件、测试文件或游戏 DLL 放进 `Workshop/content`。该目录已整理为只有本模组自己的两个发布文件。无需添加 RitsuLib 等创意工坊依赖。

订阅自己上传的版本后，如希望验证工坊下载版本，可先关闭游戏，将本地 `mods/CardCopyNumbers` 文件夹移到游戏 `mods` 目录之外。否则游戏会按自身重复模组规则选择本地或工坊版本。

上传器报错时查看 `tools/ModUploader/mod-uploader.log`。

## 源码与重新构建

需要 .NET 9 SDK。项目放在游戏目录下时，默认读取当前游戏的程序集；没有将游戏程序集打入发布包。

```powershell
powershell -ExecutionPolicy Bypass -File .\Build.ps1 -Install
```

脚本编译模组、运行逻辑测试及游戏程序集检查、更新工坊文件，并安装本地模组。关闭游戏后运行，重启生效。**继续只测试工坊版时，省略 `-Install`**，以保留本地禁用状态。

`GameDescription.bbcode.txt` 是游戏内介绍，使用字号、加粗等 Godot 富文本标签；`WorkshopDescription.bbcode.txt` 是工坊介绍，使用 Steam 支持的大小标题、加粗和列表。构建脚本会将两个文件同步到对应 JSON。

关键源码：`src/ModEntry.cs`（挂钩、名称显示、普通牌堆排序）、`src/NumberRegistry.cs`（稳定编号与预览映射）。

1.2.0：Release 编译通过，0 警告、0 错误。50 项编号逻辑检查通过，实际游戏程序集上全部 7 个 Harmony 补丁安装成功，15 项名称检查通过。覆盖仅分配 #1 时隐藏、分配 #2 后持续显示、移除后编号占用及新战斗重置。控制台测试替代了本地化服务，不等于完整游戏实机测试。

1.0.0 已由用户初步实机测试，未发现问题。**1.2.0 的标题显示规则尚待实机验证，多人尚未实机测试。** 更新并重启后建议检查：

1. 不开冻结之眼，查看抽牌堆，确认打击、防御等同名牌数字递增；抽走一张后，其他牌保持原编号。
2. 开启冻结之眼，确认牌堆真实顺序保留，同一张牌的编号不变。
3. 异蛙寄生虫加入多张感染后，确认编号不同，跨牌堆仍一致。
4. 多张凋萎的战斗中查看冲锋！！预测，核对来源编号和变化前牌堆位置；强化后的凋萎也应以 #数字 结尾。
5. 重开同一战斗并重复相同操作，核对编号复现。
6. 首次生成感染 #1 时隐藏编号；生成第二张后显示 #1、#2；移除任意一张后，剩余牌的编号仍显示。两张全部移除后，再生成一张应显示 #3。
